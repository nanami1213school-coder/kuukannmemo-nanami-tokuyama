## 非機能要件

### 非機能要件の目的

本非機能要件では、「空間メモ」のMVPが満たすべき操作性、性能、安全性、信頼性、対応環境などの品質条件を定義する。

## 1. 操作性

| ID | 項目 | 要件 |
|---|---|---|
| NFR-001 | 操作の分かりやすさ | 初めて利用するユーザーでも、部屋登録からメモ確認までの基本操作を迷わず行えること |
| NFR-002 | 操作手順 | 部屋やメモを登録するまでの操作回数を必要最小限にすること |
| NFR-003 | ボタン表示 | ボタンには、アイコンまたは文字を使用して役割が分かるようにすること |
| NFR-004 | 選択状態 | 選択中のピンカラーや写真を視覚的に判別できること |
| NFR-005 | 処理状態 | 保存、同期、アップロードなどの処理中は、進行中であることを画面に表示すること |
| NFR-006 | 完了通知 | 登録や変更が完了した場合、画面遷移またはメッセージで結果を確認できること |
| NFR-007 | エラー案内 | エラー発生時は、原因とユーザーが行うべき操作を分かりやすく表示すること |
| NFR-008 | 誤操作防止 | 削除など元に戻しにくい操作を実装する場合は、実行前に確認を表示すること |

## 2. UI・デザイン

| ID | 項目 | 要件 |
|---|---|---|
| NFR-009 | デザイン統一 | 画面全体で色、文字、ボタン、余白のルールを統一すること |
| NFR-010 | 写真中心のUI | 部屋一覧と部屋詳細では、部屋写真を中心としたレイアウトにすること |
| NFR-011 | ピンカラー | パステルカラー・ニュアンスカラーを使用し、アプリ全体の雰囲気を統一すること |
| NFR-012 | ピンの視認性 | 明るい写真や暗い写真の上でも見えるように、ピンに白い枠と薄い影を付けること |
| NFR-013 | 文字の可読性 | 文字と背景のコントラストを確保し、内容を読みやすくすること |
| NFR-014 | 画面サイズ対応 | iPhoneの画面サイズが変わっても、文字やボタンが画面外へはみ出さないこと |
| NFR-015 | キーボード対応 | 文字入力中に入力欄や保存ボタンがキーボードで隠れないこと |

## 3. 性能

| ID | 項目 | 要件 |
|---|---|---|
| NFR-016 | 起動時間 | 通常の通信環境では、アプリ起動後おおむね3秒以内に操作可能な画面を表示すること |
| NFR-017 | 操作応答 | ボタンやピンをタップした場合、ユーザーが操作を認識できる反応を速やかに表示すること |
| NFR-018 | 一覧表示 | 部屋写真を一度にすべて読み込まず、画面に必要な画像から順番に読み込むこと |
| NFR-019 | 画像最適化 | Cloudinaryへアップロードする前に、必要に応じて画像サイズと画質を調整すること |
| NFR-020 | 画像容量 | MVPでは、アップロードできる画像1枚あたりの容量を5MB以下とすること |
| NFR-021 | 画像解像度 | MVPでは、画像の長辺を最大1600ピクセル程度に縮小すること |
| NFR-022 | テストデータ量 | 10部屋、1部屋あたり20件程度のメモを登録しても、基本操作を継続できること |

## 4. 信頼性

| ID | 項目 | 要件 |
|---|---|---|
| NFR-023 | データ保持 | アプリを終了または再起動しても、保存済みデータを再取得できること |
| NFR-024 | 保存結果 | データ保存に失敗した場合、成功したように表示しないこと |
| NFR-025 | 二重登録防止 | 保存処理中に保存ボタンを複数回押しても、同じデータが重複して登録されないこと |
| NFR-026 | 画像保存整合性 | 写真のアップロードに成功した後に、画像URLとPublic IDを対象データへ保存すること |
| NFR-027 | ピン位置保持 | 端末や表示サイズが変わっても、ピンの位置が部屋画像上で大きくずれないこと |
| NFR-028 | 異常終了防止 | 通信エラーやデータ不足が発生しても、可能な限りアプリが異常終了しないこと |

## 5. セキュリティ

| ID | 項目 | 要件 |
|---|---|---|
| NFR-029 | ユーザー認証 | 部屋とメモを利用する前にFirebase Authenticationによる認証を行うこと |
| NFR-030 | パスワード管理 | パスワードをアプリ内やCloud Firestoreへ保存しないこと |
| NFR-031 | データアクセス | 部屋の所有者または共有ユーザーだけが、その部屋とメモへアクセスできること |
| NFR-032 | 共有管理 | 共有相手を追加・変更できるのは部屋の所有者だけとすること |
| NFR-033 | Firestoreルール | Cloud Firestoreのセキュリティルールを設定し、アプリ画面だけでなくデータベース側でもアクセスを制限すること |
| NFR-034 | 秘密情報 | FirebaseやCloudinaryの秘密鍵、API SecretなどをソースコードやGitHubへ登録しないこと |
| NFR-035 | 通信 | Firebase、Cloud Firestore、Cloudinaryとの通信にはHTTPSを使用すること |
| NFR-036 | Cloudinary設定 | Unsigned Uploadには、ファイル形式、容量、解像度などの制限を設定すること |
| NFR-037 | 不正アップロード対策 | CloudinaryのUpload Presetは本アプリ専用とし、不要になった場合は無効化できるようにすること |

## 6. プライバシー

| ID | 項目 | 要件 |
|---|---|---|
| NFR-038 | 写真利用説明 | 写真ライブラリを利用する目的をユーザーに分かりやすく説明すること |
| NFR-039 | 必要最小限の取得 | アプリの動作に必要な写真とユーザー情報だけを取得すること |
| NFR-040 | 位置情報 | MVPではGPSなどの現在地情報を取得しないこと |
| NFR-041 | 写真のメタデータ | 写真を再圧縮する際は、可能な範囲で位置情報などの不要なメタデータを除去すること |
| NFR-042 | メールアドレス | メールアドレスを本人確認と共有相手の指定以外の目的で使用しないこと |
| NFR-043 | 非公開データ | 所有者と共有ユーザー以外には、部屋、メモ、写真のURLを表示しないこと |

## 7. 通信・可用性

| ID | 項目 | 要件 |
|---|---|---|
| NFR-044 | 必要な通信 | アカウント登録、ログイン、同期、共有、写真アップロードにはインターネット接続を必要とすること |
| NFR-045 | オフライン表示 | 通信できない場合は、通信が必要であることをユーザーに表示すること |
| NFR-046 | 再試行 | 一時的な通信失敗が発生した場合、ユーザーが処理を再試行できること |
| NFR-047 | 外部サービス障害 | 外部サービスを利用できない場合でも、アプリが異常終了せずエラーを表示すること |
| NFR-048 | サービス依存 | FirebaseまたはCloudinaryの障害中は、一部機能を利用できない可能性があることを設計上の制約として記録すること |

## 8. 対応環境

| ID | 項目 | 要件 |
|---|---|---|
| NFR-049 | 対象端末 | iPhone向けアプリとして開発すること |
| NFR-050 | テスト端末 | iPhone 17 Pro Maxで主要機能の動作を確認すること |
| NFR-051 | テストOS | iOS 26で主要機能の動作を確認すること |
| NFR-052 | 最低対応OS | 使用するAPIと開発期間を確認した後に最低対応OSを決定すること |
| NFR-053 | 画面方向 | MVPでは縦向き表示を基本とすること |
| NFR-054 | 対象言語 | MVPでは日本語表示に対応すること |

## 9. 保守性

| ID | 項目 | 要件 |
|---|---|---|
| NFR-055 | 責務分離 | 画面表示、データ処理、外部サービスとの通信処理を可能な範囲で分離すること |
| NFR-056 | 命名 | 変数名、関数名、型名から役割を理解できる名前を使用すること |
| NFR-057 | 再利用 | 複数画面で使用するボタン、画像表示、エラー表示などは共通化を検討すること |
| NFR-058 | コメント | 処理の目的がコードだけでは分かりにくい部分に、必要最小限のコメントを書くこと |
| NFR-059 | Git管理 | 実装内容を小さな単位でGitへ記録すること |
| NFR-060 | 開発記録 | 実装内容、問題、解決方法、テスト結果をGitHubのREADMEなどに記録すること |

## 10. 費用・外部サービス

| ID | 項目 | 要件 |
|---|---|---|
| NFR-061 | 費用 | MVPでは有料サービスを使用しないこと |
| NFR-062 | Firebase | Firebase AuthenticationとCloud Firestoreの無料利用範囲で開発すること |
| NFR-063 | Cloudinary | Cloudinaryの無料利用範囲で写真を保存すること |
| NFR-064 | 利用量確認 | 外部サービスの保存容量や通信量を定期的に確認すること |
| NFR-065 | 容量超過対策 | 無料利用枠に近づいた場合は、新規アップロードを停止するなどの対応を検討すること |

## 非機能要件の優先事項

MVPでは、特に以下の要件を優先する。

1. ログインしていないユーザーがデータを操作できないこと
2. 所有者と共有ユーザーだけが部屋を閲覧できること
3. API Secretなどの秘密情報をGitHubへ登録しないこと
4. 保存やアップロードに失敗した場合にエラーを表示すること
5. 端末が変わってもメモピンの位置を保持すること
6. 写真を適切な容量と解像度に調整すること
7. iPhone 17 Pro MaxのiOS 26で正常に操作できること
8. 有料サービスを使用せずに動作すること
