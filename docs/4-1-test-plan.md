
# テスト計画

## 1. 目的

空間メモが要件定義および設計どおりに動作することを確認する。

特に、次の主要機能を重点的にテストする。

- アカウント登録とログイン
- 部屋の登録と表示
- 部屋画像上へのメモ登録
- メモの確認と編集
- Firebaseへのデータ保存
- Cloudinaryへの画像保存
- 複数ユーザー間での部屋共有
- 権限による操作制限

## 2. テスト対象

| 分類 | 対象 |
|---|---|
| 認証 | アカウント登録、ログイン、ログアウト |
| 部屋 | 一覧、登録、詳細、画像変更 |
| メモ | 登録、一覧、詳細、編集、ピン表示 |
| 画像 | 写真選択、アップロード、表示 |
| 共有 | メンバー一覧、追加、権限制御 |
| 設定 | ユーザー情報、アプリ情報、ログアウト |
| データ | Firestoreへの保存、取得、同期 |
| エラー | 入力エラー、通信エラー、権限エラー |

## 3. テスト対象外

次の将来機能は今回のテスト対象外とする。

- 3Dスキャン
- AR表示
- AI機能
- 通知機能
- 組織・役職管理
- QRコード・バーコード
- レポート出力
- Android版・Web版
- 部屋およびメモの削除
- メモピンの移動
- Cloudinary上の不要画像の自動削除

## 4. テスト環境

| 項目 | 内容 |
|---|---|
| 開発環境 | Xcode |
| 言語 | Swift |
| UI | SwiftUI |
| 実機 | iPhone 17 Pro Max |
| OS | iOS 26 |
| 認証 | Firebase Authentication |
| データベース | Cloud Firestore |
| 画像保存 | Cloudinary |
| 写真選択 | PhotosUI |
| 通信 | Wi-Fiまたはモバイル通信 |

実機に加えて、必要に応じてiOS Simulatorを使用する。

## 5. テストアカウント

共有機能を確認するため、2つのテストアカウントを用意する。

| アカウント | 役割 |
|---|---|
| テストユーザーA | 部屋のowner |
| テストユーザーB | 共有されたeditor |

実在する個人情報や本番用パスワードは使用しない。

## 6. テスト用データ

| データ | 使用例 |
|---|---|
| 部屋名 | リビング、会議室A |
| 部屋写真 | 個人情報を含まない室内写真 |
| メモタイトル | エアコンの型番 |
| メモ本文 | 型番：ABC-1234 |
| ピンカラー | sage、dusty-pink |
| 添付写真 | 個人情報を含まない備品写真 |
| 共有相手 | テストユーザーB |

## 7. テストの種類

### 7.1 機能テスト

各機能が機能要件どおりに動作するか確認する。

### 7.2 画面テスト

- UI設計どおりに項目が表示されるか
- 画面から文字やボタンがはみ出さないか
- ボタンをタップできるか
- 画面遷移が正しいか
- キーボードで入力欄が隠れないか

### 7.3 入力チェックテスト

- 必須項目が空の場合
- 文字数を超えた場合
- メールアドレス形式が不正な場合
- パスワードが一致しない場合
- 大きすぎる画像を選択した場合

### 7.4 外部サービス連携テスト

- Firebase Authenticationへ登録できるか
- Firestoreへデータが保存されるか
- Firestoreからデータを取得できるか
- Cloudinaryへ画像をアップロードできるか
- Cloudinaryの画像をアプリで表示できるか

### 7.5 共有・権限テスト

- ownerが共有ユーザーを追加できるか
- editorが共有された部屋を確認できるか
- editorがメモを追加・編集できるか
- editorが部屋画像を変更できないか
- editorが共有管理画面へ移動できないか

### 7.6 通信エラーテスト

- オフライン状態で読み込みを行った場合
- オフライン状態で保存を行った場合
- Firebaseとの通信に失敗した場合
- Cloudinaryへのアップロードに失敗した場合
- 通信失敗後に再試行できるか

### 7.7 データ保持テスト

- アプリを終了して再起動してもログイン状態が保持されるか
- 登録した部屋が再起動後も表示されるか
- 登録したメモが再起動後も表示されるか
- 異なる端末またはSimulatorでも共有データを確認できるか

## 8. テスト実施順序

次の順番でテストする。

1. アプリのビルド確認
2. 画面表示と画面遷移
3. 入力チェック
4. アカウント登録・ログイン
5. 部屋登録
6. メモ登録・編集
7. 画像アップロード
8. 共有機能
9. 権限制御
10. 通信エラー
11. 実機での最終確認

主要機能から順番に確認し、重大な問題を先に修正する。

## 9. テスト開始条件

次の条件を満たしてからテストを開始する。

- Xcodeでビルドが成功する
- Firebaseの設定が完了している
- Cloudinaryの設定が完了している
- テストアカウントを作成できる
- MVP対象画面を操作できる
- テスト用画像を用意している

## 10. テスト完了条件

次の条件を満たした場合、テスト完了とする。

- MVPの主要機能に関するテストがすべて実施済み
- アプリがクラッシュする問題が残っていない
- データが失われる問題が残っていない
- 認証や権限に関する重大な問題が残っていない
- GitHubに既知の問題を記載している
- iPhone 17 Pro Max、iOS 26で最終動作を確認している

## 11. 不具合の重要度

| 重要度 | 内容 | 例 |
|---|---|---|
| Critical | アプリを提出できない問題 | 起動しない、データ漏えい |
| High | MVPの主要機能を利用できない問題 | ログインできない、保存できない |
| Medium | 一部の機能に問題がある | エラー表示が不適切 |
| Low | 見た目や軽微な問題 | 余白、文字位置のずれ |

CriticalとHighの不具合は、提出前に必ず修正する。

## 12. テスト結果の記録

テスト結果は次の形式で記録する。

| 項目 | 内容 |
|---|---|
| テストID | テスト項目を識別する番号 |
| テスト内容 | 確認する操作 |
| 前提条件 | テスト前に必要な状態 |
| 操作手順 | 実際に行う操作 |
| 期待結果 | 正常な場合の結果 |
| 実行結果 | PassまたはFail |
| 備考 | 不具合や確認事項 |

## 13. 証跡

必要に応じて、次の証跡を保存する。

- 動作確認時のスクリーンショット
- Simulatorまたは実機の画面録画
- エラーメッセージのスクリーンショット
- Firebaseに保存されたテストデータ
- Cloudinaryに保存されたテスト画像

パスワード、トークン、API Secretなどの秘密情報は証跡に含めない。
